# Project documentation: UDA branches for an adaptive model soup on HAR

This folder documents the student work in this repository. The supervisor's `README.md` in the repository root describes the data, the preprocessing and the source-only training and is not repeated here.

## Goal and research question

Several unsupervised domain adaptation (UDA) methods are trained separately for the **same** transfer, each starting from the same source-only model. Their weights are then to be averaged (a model soup). The research question from the project kickoff is: **can an averaged model outperform its individual UDA branches?**

- Source data are labelled. Target data may be used in training only without labels; target labels appear only in the final evaluation.
- Data: human activity recognition from inertial sensors (wrist and ankle, accelerometer, gyroscope, magnetometer; 18 channels, 50 Hz, windows of 150 samples with 50 % overlap).
- Experiment families: cross-dataset (PAMAP2, RealWorld, MHEALTH; 5 shared activities), cross-gender (PAMAP2, RealWorld) and cross-age (RealWorld, below 30 and 30 plus). Together 12 transfers.

## Status

| Phase | Content | Status |
|---|---|---|
| 1 | Evaluate the source-only baseline of every transfer | done |
| 2 | Train three UDA methods separately on every transfer, starting from the source-only model, and compare them with the baseline | done for Deep CORAL, DANN and DSAN on 12 transfers and 5 seeds |
| 2b | Uniform soup of the three branches per transfer (stage 3, averaging at the end) | done on 12 transfers and 5 seeds, with two batch-normalisation variants and an output ensemble as comparison |
| 3 | When to average: at the end, per epoch or per batch | not started |
| 4 | How to average: uniform or weighted without target labels | not started |

Headline result of phase 2 (weighted F1 on the target test split, mean over the 12 transfers, mean ± SD over 5 seeds): baseline 41.9 ± 1.0 %, Deep CORAL 45.7 ± 1.8 %, DANN 52.6 ± 1.0 %, DSAN 52.7 ± 3.0 %. The uniform soup of the three branches reaches 43.0 ± 2.7 % (averaged batch-normalisation statistics) and 42.9 ± 2.4 % (re-estimated on target), below the mean of its branches (50.3 ± 1.5 %) in every seed. All numbers, tables and figures are in [results.md](results.md); read them together with [limitations.md](limitations.md).

## Setup

The environment is the one of the supervisor's README:

```bash
conda env create -f environment.yml
conda activate adaptive_soup_student
```

or

```bash
python -m pip install -r requirements.txt
```

All commands are run from the repository root.

**Device.** Our runs were computed on an Apple M1 with the MPS backend, which is the default of our scripts. Another device can be chosen with `--device cuda` or `--device cpu`. PyTorch does not guarantee bitwise reproducible results on MPS, and results from another device will differ slightly from the tables here.

**Data.** The prepared data and the supplied source-only models are stored with Git LFS in the supervisor's repository:

```bash
git lfs install
git lfs pull
```

A download through a fork counts against the LFS quota of the supervisor's repository, so pull the LFS files **once** and keep them.

**Checkpoints of our runs are not in the repository.** `results/**/*.pt` is excluded by `.gitignore`. The repository contains the code, the predictions of every run (`predictions/*.npz`), the training logs, the run configurations and all tables. With these, every table and figure can be rebuilt without retraining; the domain probe is the only analysis that needs the checkpoints. To get checkpoints, retrain with the commands in [pipeline.md](pipeline.md).
